# NASA APOD Gallery

An ASP.NET Core MVC application that fetches NASA Astronomy Picture of the Day (APOD) records for a selected date range, saves new records to SQL Server using ADO.NET, and displays saved images in a responsive gallery.

## Technologies

- .NET 10 and ASP.NET Core MVC with Razor views
- SQL Server / SQL Server Express
- Microsoft.Data.SqlClient (ADO.NET with parameterized SQL; no Entity Framework)
- HttpClient and System.Text.Json
- Bootstrap

## Prerequisites

- .NET 10 SDK
- Visual Studio 2026 with the **ASP.NET and web development** workload, or another editor with the .NET CLI
- A running SQL Server or SQL Server Express instance
- SSMS or Visual Studio SQL Server Object Explorer to run the database script
- Internet access for NASA requests and image loading
- A NASA API key from [NASA Open APIs](https://api.nasa.gov/)

## Setup

### 1. Create the database

Connect to your SQL Server instance using SSMS or SQL Server Object Explorer. The default local Express instance used by this project is `.\SQLEXPRESS` with Windows Authentication.

Run [Database/CreateDatabase.sql](Database/CreateDatabase.sql). It creates `NasaApodGalleryDb` and `dbo.ApodEntries`, including the unique constraint on the APOD date.

The script does not delete data. It skips an existing database/table; it does not upgrade an older table with missing columns. For local development, enable **Trust Server Certificate** in the connection dialog if needed.

### 2. Configure local settings

In Visual Studio, right-click the **NasaAPODGallery project** and select **Manage User Secrets**. Save the following, replacing the key placeholder:

```json
{
  "Nasa": {
    "ApiKey": "YOUR_NASA_API_KEY"
  },
  "ConnectionStrings": {
    "DefaultConnection": "Server=.\\SQLEXPRESS;Database=NasaApodGalleryDb;Integrated Security=True;Encrypt=True;TrustServerCertificate=True"
  }
}
```

Change `Server` for a different SQL Server instance. The Windows account running the application needs permission to read and insert records in the database.

Alternatively, run these commands from the repository root:

```powershell
dotnet user-secrets set "Nasa:ApiKey" "YOUR_NASA_API_KEY" --project NasaAPODGallery
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=.\SQLEXPRESS;Database=NasaApodGalleryDb;Integrated Security=True;Encrypt=True;TrustServerCertificate=True" --project NasaAPODGallery
```

User Secrets are stored outside the repository and loaded in Development. Do not commit API keys or connection credentials. User Secrets are a development configuration mechanism, not an encrypted production secret store. `TrustServerCertificate=True` is used for the local development server; use a trusted certificate for deployment.

### 3. Run

Open `NasaAPODGallery.slnx` in Visual Studio, select the HTTPS launch profile, and run the project.

Or use the CLI from the repository root:

```powershell
dotnet restore NasaAPODGallery/NasaAPODGallery.csproj
dotnet dev-certs https --trust
dotnet run --project NasaAPODGallery/NasaAPODGallery.csproj --launch-profile https
```

Open [https://localhost:7118](https://localhost:7118), or use the address printed by the application if launch settings have changed.

## Usage

1. Select a start and end date, up to 31 days inclusive.
2. Click **Fetch and save**.
3. The application requests NASA data, inserts dates not already stored, and redirects to the gallery.
4. The gallery reads saved records from SQL Server, newest first. Repeating a range skips existing dates.

Images are loaded from NASA URLs; image files are not downloaded into SQL Server. Video records and records without image URLs display a placeholder. NASA alt text is used where available, with the title as a fallback.

## NASA API migration

The implementation uses NASA's replacement WordPress endpoint:

```text
https://science.nasa.gov/wp-json/wp/v2/apod-basic/
```

Date ranges use `date_from` and `date_to` in `yyMMdd` format, rather than the legacy `start_date` and `end_date` parameters. For example:

```text
https://science.nasa.gov/wp-json/wp/v2/apod-basic/?date_from=261020&date_to=261022
```

The application also sends the configured `api_key`. The replacement endpoint was observed to accept requests without a key; sending one does not establish that it is validated or required.

The response is deserialized as a JSON array. `url` is stored separately from `hdurl`: the gallery uses `hdurl` for images, while `url` commonly points to the NASA article. Additional metadata includes `post_id`, `permalink`, `credit`, `copyright`, and `alt`. `basic_html` and `basic_html_url` are intentionally omitted.

`ServiceVersion` is nullable because the replacement response may omit the legacy `service_version` field. `SavedAt` is generated by SQL Server in UTC. The local `Id` is separate from NASA's `PostId`.

## Project structure

```text
Database/CreateDatabase.sql       Database and table setup
NasaAPODGallery/
  Controllers/HomeController.cs   Handles page and fetch requests
  DTOs/ApodDto.cs                  Maps NASA JSON properties
  Models/ApodEntry.cs              Represents a saved database record
  Services/NasaApodService.cs      Calls NASA and deserializes JSON
  Repositories/ApodRepository.cs   Executes parameterized SQL
  Views/Home/Index.cshtml          Date form and saved-record gallery
  Program.cs                      Registers services and configures MVC
```

The controller maps DTOs into database models. The repository inserts only new dates using `WHERE NOT EXISTS` with locking hints; a database unique constraint also prevents duplicate dates. SQL rows are mapped back into model objects for the view.

## Verification

Build with:

```powershell
dotnet build NasaAPODGallery/NasaAPODGallery.csproj
```

Suggested manual checks:

- Fetch October 20–22, 2026 and inspect the gallery and saved SQL rows.
- Fetch the same range again: the new-record count should be zero.
- Fetch an overlapping range: only previously unsaved dates should be inserted.
- Refresh the homepage: saved records should remain visible without another fetch.
- Submit reversed dates or a range longer than 31 days: validation should reject it.
- Use a narrow viewport and check the gallery layout.

Temporary diagnostic routes currently available are `/Home/TestNasa` and `/Home/TestDatabase`. Remove these actions before publishing if they are not needed.

## Current limitations

- The NASA service currently reads one response per request and does not implement pagination. Completeness for larger ranges should be verified against NASA's current response limits.
- Fetching existing dates does not refresh their metadata.
- HTTP failures show a message; timeout, invalid JSON, and database failure handling can be improved.
- Credit and copyright metadata are stored but are not currently displayed in the gallery.
- No automated test suite is included.
- The current build reports vulnerability warnings for the transitive `System.Security.Cryptography.Pkcs` 9.0.18 dependency. Review and resolve these before deployment.
